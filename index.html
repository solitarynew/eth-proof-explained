01

先把“有没有解”
变成“有多少个解”

SAT 的输入是一串逻辑条件。给每个变量赋值后，公式要么成立，要么不成立。试着点击下面的变量，看看这次赋值是不是一个解。

动手试试 · SAT示例：3 个变量
F = (a ∨ b) ∧ (¬b ∨ c)

这个例子一共有 2³ = 8 种赋值，其中 4 种满足公式。论文处理的是任意固定 k 的 k-SAT，3-SAT 只是特别重要的情况。

论文要计算的是 #F，也就是满足公式的赋值数量。只要知道 #F，就知道是否有解：#F > 0 表示有解。

#F = ∑所有赋值 x ∏所有子句 e Φe(x)

这里的 Φ 是子句的指示多项式：子句成立时为 1，不成立时为 0。所有子句的值相乘，只要有一个不成立，乘积就是 0；再对所有赋值求和，得到的就是解的个数。

到这里还没有加速。我们只是把逻辑问题换成了一个代数求和，以便后面使用多项式和线性代数。
02

先固定共享信息，
再让各组分别计算

跨组子句会让变量互相牵连。一个重要思路是：如果另一组的信息只需要通过少量摘要传递，固定这些摘要后，就可以把工作拆开。

互动例子 · 共享摘要同一个公式：F = (a ∨ b) ∧ (¬b ∨ c)

将 a 放在 A 组，将 b、c 放在 B 组。A 组只需要 B 组给它一个摘要：b 的值。选择摘要，看看两组如何独立计数。

B 组 · 枚举 c

两种摘要的结果再相加：2 + 2 = 4 个解。这里的摘要恰好是一个布尔变量；论文中的摘要可以是多变量的线性组合，而且处理的是变形后的代数表达式。

核心代价：组内枚举变便宜了，但枚举所有摘要也要花时间。只有摘要足够少、取值范围足够受控，整体才可能变快。

04

真正要同时过的
三道成本关

论文并不是说“分组 + 插值”这几个词本身就能解决 SAT。难的是为任意输入构造合适的变形，并严格证明所有成本加起来仍足够小。

组内枚举每组仍要尝试赋值，组必须足够小。
共享摘要要枚举摘要的取值，数量和范围必须受控。
插值信息多项式次数和泰勒系数的计算不能太贵。

论文通过一套线性代数构造处理这些互相牵制的条件。粗略地说：利用交换结构与集中现象，让大部分方向可以用低次数表达式处理；少数例外通过共享摘要处理。随后还要证明能在一般的固定 k-SAT 上控制额外开销。

论文主张的运行时间 · k 固定
polyk(n, m) · 2Ok(n log log n / √log n)

因为 (log log n)/√log n → 0，指数是 o(n)。它在渐近意义上是亚指数时间；这不代表已经证明它在实际规模上胜过现有 SAT 求解器。

公开的 Lean 形式化覆盖一个稍弱但仍为亚指数的时间界。形式化为结果提供了重要证据，形式化陈述与通常 ETH 的对应关系及完整数学论证仍需专家核查。
05

如果成立，改变了什么？

✓ 对 ETH 为条件的复杂度下界，需要重新理解其前提；原来的条件推理本身不一定有错。
✓ 为 SAT 和相关问题提供新的算法方向，但要得到实际可用的改进仍需研究。
≠ 这不等于 P = NP。亚指数时间仍然可以远大于多项式时间。
≠ 这不自动说明所有 NP 问题都能以各自输入规模的亚指数时间解决，也不意味着现有密码系统马上被攻破。
