先说人话

它想解决的是：
能不能不用试遍所有可能？

你有一堆只有开 / 关两种状态的开关，还有一串必须满足的规则。最笨的方法是：把所有开关组合都试一遍。开关越多，组合数增长得越快。

论文研究的是：有没有一种保证对任何输入都正确、最坏情况下增长更慢的算法？OpenAI 声称找到了。下面先不急着谈证明，先弄明白题目。

阅读边界：本文用小例子讲思路。例子能帮助理解，但不是论文算法的完整实现，也不能证明论文正确。OpenAI 已公开论文和 Lean 形式化材料；独立专家正在组织核验。公告 ↗

01 / 先认识输入

SAT 就是在问：
有没有一种开关组合满足规则？

令 a、b、c 是三个开关：1 表示开，0 表示关。下面有两条规则：

同一个例子贯穿全文
F = (a ∨ b) ∧ (¬b ∨ c)

∨ 表示“或者”：至少一个为 1。¬ 表示“取反”：¬b 为 1 意味着 b 为 0。∧ 表示“并且”：两条规则都要满足。

规则 1：a ∨ b

a 和 b 至少有一个是 1。

规则 2：¬b ∨ c

b 为 0，或者 c 为 1。

点一下开关，看看当前组合是否满足两条规则：

看完整的 8 种组合
abc规则 1规则 2结果

每个开关有两种状态：3 个开关有 2 × 2 × 2 = 8 种组合；n 个就有 2n 种。SAT 问的是“有没有解”；论文做得更强，试图精确数出所有解，记为 #F。这个例子的答案是 4。

3-SAT 是什么？每一条“或者”规则最多包含三个变量。上面每条只有两个，也属于允许的范围。变量和规则的数量可以很大。

02 / 为什么想到拆分

如果可以分组，
就不必每次都拼出完整组合

假设两组变量完全互不影响：A 组有 3 种合法选择，B 组有 2 种，那么合起来有 3 × 2 = 6 种。各组分别数，再相乘，比枚举完整组合容易。

但我们的例子有麻烦：变量 b 出现在两条规则里。把 a 放进 A 组、b 和 c 放进 B 组时，A 组计算规则 1 也需要知道 b。

亲手拆一次

先固定跨组信息 b，再分别数两个组。点选 b 的值：

A 组：数 a

B 组：数 c

两种情况合起来：b = 0 时 2 个解；b = 1 时 2 个解，总共 4 个。

这里把 b 看成一条“共享信息”。在真正的算法里，论文用的是一些变量的线性组合作为共享信息，例如 x₁ + x₂ − x₃。固定这些信息后，变形后的表达式可以一组一组算。

但分组不是免费午餐：如果共享信息太多，光枚举它们所有可能的值又会爆炸。论文必须证明共享信息足够少。

03 / 论文的第一步

把“满足规则”
改写成普通算术

下面只用加减乘。因为 a 和 b 是 0 或 1，a ∨ b 可以写为：

Φ₁(a,b) = 1 − (1 − a)(1 − b)

试想：只有 a = 0 且 b = 0 时，后面的乘积才是 1，所以结果是 0。其他情况结果都是 1。也就是说，这个算式恰好充当了规则 1 的“打分器”。

Φ₂(b,c) = 1 − b(1 − c)

规则 2 同理：只有 b = 1 且 c = 0 时，它不满足，算式的值为 0。

两条规则都要成立，因此把两个打分器相乘；要数所有解，就把 8 种赋值的得分加起来：

#F = Σa,b,c ∈ {0,1} Φ₁(a,b) × Φ₂(b,c) = 4

看懂这个求和就够了：每个合法组合贡献 1，不合法组合贡献 0。到这里还没有加速，只是把逻辑计算翻译成了代数，方便接下来变形。

04 / 先亲眼看一次

变形，再把答案算回来

论文引入一个参数 T，制造一个新的算式 H(T)。它在 T = 0 时恢复原来的问题；在一些其他位置，算式更容易拆分。

先看一个可以手算的小模型。它只是解释“变形 + 还原”，不是论文的完整构造。

一个具体的代数变形

在第一个打分器里，把 b 换成 b(1 − T/2)：

H(T) = Σ [1 − (1−a)(1−b(1−T/2))] × [1−b(1−c)]

这个 H(T) 是为了说明而设计的。T ≠ 0 时，它的项可能是小数，因此 H(T) 不一定是某个 SAT 问题的解的个数。

为什么可以从别处算回 H(0)？

这个玩具例子里的 H(T) 是一条直线：H(T) = 4 − T/2。一条直线只要知道两个点，就能确定整条线。这里知道 H(1) = 3.5 和 H(2) = 3，所以：

H(0) = 2 × H(1) − H(2) = 2 × 3.5 − 3 = 4

这就是插值：知道函数属于某种受限制的多项式，再利用足够多的位置上的信息，还原出想知道的值。它不需要你原来就知道曲线的具体公式。

这里不要误会：这个小例子中，H(2) 确实能直接拆开；H(1) 我们仍然通过枚举算出。这个演示本身没有加速。论文真正的难题，是为许多位置同时构造可高效计算的信息，再保证还原成本也不爆炸。

05 / 回到论文

论文的算法，
从输入到答案到底走了什么路？

论文第 2 节先讲一个简化版本：每条规则最多 3 个变量，而且每个变量出现次数也有限。核心算法按下面的顺序运行：

① 先把规则变成打分器。 每条规则变成一个满足时为 1、否则为 0 的多项式。把它们相乘，再对所有赋值求和，目标就是 #F。
↓
② 构造一整个多项式 H(T)。 给规则读取变量的方式做特殊替换，保证 T = 0 时原样恢复；在许多其他计算点，跨组依赖能通过少量共享摘要表达。
↓
③ 在每个计算点，固定摘要、分组计算。 枚举摘要的可能值；在每个值下，逐组枚举本组变量、算组内贡献，再把各组合并。
↓
④ 多算一些“局部变化信息”。 仅有各点的 H(t) 还不够。论文计算这些点的若干泰勒系数，可以把它理解为曲线在该点附近的更多信息；论文用容斥把它们转化为仍可分组计算的求和。
↓
⑤ 插值还原 H(0)。 已知 H 的次数上界，又收集了足够多的点和局部信息，就可以通过插值恢复 #F。
# 论文的思路示意，不是可直接运行的实现 构造 H，使 H(0) = 原问题的解数 for 计算点 t: for 需要的局部信息: for 共享摘要的可能取值: 分别计算各组的贡献，再合并 用所有计算点与局部信息插值 返回 H(0)

最关键的魔法：第 ② 步怎么可能做到？

论文需要同时做到两件看上去互相冲突的事：在 T = 0 原样保留每个变量；在很多不同的点，让每条规则只需要自己的组和少量摘要。一个基本积木是 1 − T/2：在 0 时等于 1，在 2 时等于 0。乘上它，就能让某项在指定点消失，同时在 0 处保留。

但需要消失的点越多，乘进去的因子越多，多项式次数就越高；次数越高，恢复所需的信息也越多。论文用交换矩阵和线性代数构造，让大部分方向能由低次数表达式处理，把少数例外方向放进共享摘要。证明的核心是：能否对任意输入把这些对象全部构造出来，并同时控制大小。

“大部分方向”和“少数例外”到底指什么？

它们是论文在一个辅助向量空间中选出的基向量，不是说“大部分 SAT 输入容易”。论文分析一组交换矩阵的特征方向；这些方向对应的某个数量呈二项分布，大部分集中在中间。它用低次数多项式处理集中区域，把剩余的基方向作为需要额外测量的信息。具体矩阵构造见论文第 2.7 节和第 4 节。

一般公式怎么办？

上面先假设每个变量出现次数有限。论文再用稀疏化把一般输入拆成若干较稀疏的子问题，并通过变量复制、加相等约束等方式，转为前面的受限形式；最后把各子问题的计数加起来。论文还给了更精细的路径，以得到更好的时间上界。关键不只是能转换，还要证明拆分数量和新增变量的成本保持可控。

06 / 为什么可能快

三笔账，都必须算得过来

只说“拆成小组”远远不够。真正的总开销来自三个地方，它们是乘在一起的：

① 组内枚举

每组仍要试变量组合。组要足够小。

② 摘要枚举

每种共享信息的取值都要处理。摘要不能太多。

③ 还原信息

计算点、局部变化信息和插值都要花时间。

论文声称通过精心选择参数，让三笔账加在指数里之后，相对于 n 都变得越来越小，从而得到亚指数时间。对固定 k，论文主结果写作：

polyk(n,m) × 2Ok(n log log n / √log n)

不需要会推导这个式子，只需要注意：它的指数相对 n 的比例，在 n 足够大时趋近于 0。这叫 2o(n)，即亚指数时间。

亚指数是多项式时间吗？

不是。例如 2 的 √n 次方是亚指数，但增长仍然可以远快于 n²、n³ 等多项式。论文里的式子也不意味着现实中立即比现有 SAT 求解器更快：隐藏常数和达到渐近效果需要的规模都可能很大。

为什么它会推翻 ETH？

ETH 的一种常见表述认为，最坏情况下的 3-SAT 不存在以 2 的 o(n) 次方、乘输入大小的多项式时间求解的算法。论文声称对固定 k 的 k-SAT 给出这种算法，取 k = 3 就与 ETH 矛盾。形式化结果覆盖的时间界稍弱，但仍是亚指数。

07 / 最后厘清

读完后应该记住什么？

论文的主张：通过可分组的代数变形、共享摘要和插值，精确计算 SAT 的解数，并给出亚指数时间上界。
最重要的难点：对任意输入同时构造出低次数变形、少量共享摘要和可负担的插值信息。
目前的状态：OpenAI 已发布论文和 Lean 形式化材料；独立专家正在核验。不能把这篇网页当作对完整证明的验证。
不意味着：它不等于证明 P = NP，也不自动意味着所有 NP 问题都有按各自输入规模计算的亚指数算法。

继续读论文时，可以先读第 2 节的技术概览，再看第 3、4 节的计数算法和构造；一般公式的处理在第 6 节和附录中。
